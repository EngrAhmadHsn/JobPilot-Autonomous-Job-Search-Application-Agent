## Design authority & the responsive dimension contract

The design has exactly **four frames** (19 screens × 4 sizes + variants), scale 1.0:

| Frame | Chrome | Tailwind mapping |
|---|---|---|
| **1440×1000** | collapsed 72px rail + top bar | ≥1024 (`lg:`) — rail visible, max-width container |
| **1024×1000** | collapsed 72px rail + top bar | ≥1024 — same chrome, narrower content |
| **768×1024** | **no rail** — dark top bar + 4-slot bottom nav | <1024 — mobile chrome (current `lg` boundary already correct; verified) |
| **390×844** | top bar + bottom nav | <1024 — mobile chrome |

Binding on every workstream:

1. **Expanded sidebar is a user toggle only at ≥1024** (`13 · Expanded navigation · 1440/1024`). At **<1024 it is an overlay drawer over dimmed content** (`13 · Expanded navigation · 768/390`). Our `nav-drawer` (Sheet) is restyled to match those files (labeled rows, lime active pill, avatar footer, ~58% width at 768 / near-full at 390).
2. At ≥1024 the approved **overlay expansion** stands (user-directed deviation from the design's push reading): content gutter constant at 72px, expanded rail floats over content — zero reflow.
3. Per-screen small-size facts: metric tiles 2×2 at ≤768; Discover split-pane only ≥1024 (stacked + page scroll below); Review step-chips wrap at 390; Account tabs wrap at 768; **filters modal widths 480 / 350** → one responsive dialog.
4. The audit gains the design's exact frames: sweep **1440×1000, 1024×1000, 768×1024, 390×844** (plus existing 1280/900/360).

## Commit policy — atomic per feature (user-directed)

**One commit per feature, never per workstream.** Each commit cut by the lead, verified green (tests for the touched area) against its own tree before the next, repo message style (`feat:/fix:/test:/docs: … (ws-NN)`). Parallel agents touch disjoint files; the lead sequences feature commits as work merges. Representative cutting:

- WS-43 → 6: rail overlay geometry · toggle/icon size · radius unification · footer alignment · Home color fix · nav-drawer restyle.
- WS-44 → 4–5: BE workplace filter + locations endpoint; FE filters modal + chips; default selection; pane scroll.
- WS-45 → 3–4: answers table + routes + plan merge; Review answering UI; profile context questions; gaps/EEO UI.
- WS-46 → 3–4: profile documents pagination; account screen; BYOK move + menu link; audit-script frames.
- WS-47 → 2–3: PUT /tailored + revalidation; editor UI; keyword-rail restyle.
- WS-48 → 1 commit per primitive rebase + 1 for provider wiring + 1 for hand-motion surfaces.
- WS-49 → cleanup (1); docs (1).

Staging is per-feature deliberate (known `git add` sweeping trap — stage explicitly, `git status` before each commit).
