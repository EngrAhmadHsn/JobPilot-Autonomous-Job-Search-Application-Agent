## Context

Resume Studio has two separate problems. Prior live runs recorded `503` responses from model timeouts and provider unavailability. Separately, **Open in Studio** passes only the job ID, and the screen never reads the saved draft, so reopening or refreshing drops back to the pre-run view. The previous visual sweep also checked the job picker, not the completed draft shown in Figma. One confirmed mismatch: the evidence card stacks at 1024 px in the app, but sits beside the document in the approved frame.

## Changes

1. **Make generation recover where it can and fail clearly where it can’t.** In `src/resume/pipeline.py` and `src/api/routes/tailoring.py`, use the existing `get_generate_fn` test seam to reproduce failures separately in listing research and draft generation. If optional research fails with a recoverable timeout or bad output, use a grounded, listing-only summary rather than blocking generation. Keep credential, quota, and draft-generation failures explicit; don’t silently change providers for personal keys, present an unchanged résumé as tailored, or log résumé text or credentials. Keep the existing API and provider retry policy. In Studio, keep the last good draft visible on a failed rerun and direct credential errors to Account → Model credentials.
2. **Make the saved draft the source of truth.** In `tailor-screen.tsx` and `profile-screen.tsx`, put the exact tailoring ID in the Studio URL after generation and in the library link. Reuse `api.getTailored` and the record’s own `profile_id` for the Original and diff, even if another résumé is active. Check that the record belongs to the job in the URL; handle a missing record without starting another generation. Use the saved PUT response for the visible reports, letter, and edited status. In `studio/resume-editor.tsx` and `cover-letter-panel.tsx`, omit changes to nonexistent sections and refresh the letter when its saved text changes. Keep failed edits in the editor.
3. **Keep downloads tied to the right draft.** In the existing tailoring render/persistence path (`tailoring.py`, `resume/pipeline.py`, and `resume/edit.py`), allocate the tailoring ID before rendering so separate runs for one profile and job no longer overwrite each other’s files. Save edits only to the addressed draft; move a legacy shared path to a draft-specific target on its next successful render. Preserve scoped access and leave existing files alone rather than claiming old overwritten bytes can be recovered. No change to application preparation, approval, or submission.
4. **Match the completed Studio to the agreed Figma.** Use [1440](https://www.figma.com/design/7K6iWR1nxcAMMOiIYEUJW8/Job-Pilot?node-id=16-82), [1024](https://www.figma.com/design/7K6iWR1nxcAMMOiIYEUJW8/Job-Pilot?node-id=49-5512), [768](https://www.figma.com/design/7K6iWR1nxcAMMOiIYEUJW8/Job-Pilot?node-id=49-7854), and [390](https://www.figma.com/design/7K6iWR1nxcAMMOiIYEUJW8/Job-Pilot?node-id=49-10557). Keep the document and independently sized evidence card side by side at 1440/1024, stacked at 768/390. Match the wrapping pills, paper insets, clay strike-through and lime diff, evidence hierarchy, and Review CTA in `tailor-screen.tsx` and `screens/studio/`. Reuse the existing tokens and controls. Preserve real edit/save/discard, factuality warnings, Validation and Research, and truthful file-format labels. Don’t add decorative formatting buttons that don’t work or change the shared shell.
